## Что потребуется

Одинаковая версия AntHub на клиенте и сервере и настроенная [PostgreSQL](README.md#postgresql). При включении Auth уберите AuthLogic и другие моды авторизации. Импорт аккаунтов не предусмотрен.

<a id="setup"></a>

## ⚙️ Настройка

В `config/anthub-auth.toml` укажите режим и перезапустите сервер:

```toml
mode = "hybrid"
allowRegistration = true
minimumPasswordLength = 6
```

| Параметр                | Значение                                                      |
| :---------------------- | :------------------------------------------------------------ |
| `mode = "false"`        | Auth выключен, действуют обычные правила Minecraft.           |
| `mode = "base"`         | Регистрация и вход с паролем сервера.                         |
| `mode = "hybrid"`       | Пароль и возможность привязать официальный Minecraft-аккаунт. |
| `allowRegistration`     | Разрешить самостоятельную регистрацию новых аккаунтов.        |
| `minimumPasswordLength` | Минимум нового пароля: от 6 до 128 символов, по умолчанию 6.  |

Режим — строка: `"false"` тоже пишется в кавычках. Новый минимум пароля применяется к регистрации, смене и сбросу, но не мешает входить со старым паролем.

> [!NOTE]
> `online-mode` в `server.properties` — отдельная настройка. Для игроков без официального аккаунта требуется `online-mode=false`. При `true` Minecraft сначала проверяет официальный аккаунт. AntHub не меняет это значение.

## 👤 Аккаунт

При первом входе игрок создаёт пароль сервера. Наличие такого же ника у Mojang не мешает регистрации и не даёт доступа к чужому серверному аккаунту.

В **«Безопасности аккаунта»** доступны:

- смена пароля;
- список устройств и отзыв доступа;
- в `hybrid` — привязка и отвязка официального Minecraft-аккаунта.

Привязка требует текущего пароля и подтверждённой официальной сессии в лаунчере. Отвязка — текущего пароля. Один официальный аккаунт можно привязать только к одному серверному аккаунту. Обе операции отзывают запомненные устройства и остальные сеансы.

**«Запомнить меня»** сохраняет доступ максимум на 30 дней. На аккаунт доступно до 10 устройств; привязки к IP нет.

### UUID и игровые данные

При регистрации AntHub закрепляет исходный UUID Minecraft — идентификатор, к которому привязаны инвентарь и права. Затем регистр ника и способ входа его не меняют. Официальный UUID хранится отдельно как привязка.

На offline-сервере **до регистрации** регистр имени влияет на UUID: первый вход и добавление в whitelist выполняйте с тем же написанием ника, которое использовалось раньше.

Выключение Auth возвращает обычные правила Minecraft. Автоматического переноса инвентаря и прав между разными UUID нет.

## 🛟 Восстановление доступа

1. Администратор проверяет, что обращается владелец аккаунта.
2. Создаёт приглашение для сброса.
3. Передаёт его игроку лично.
4. Игрок выбирает восстановление в форме входа и вводит приглашение и новый пароль.

Приглашение одноразовое, действует **15 минут**. После сброса отзываются устройства и сеансы, а официальная привязка удаляется.

### Через консоль сервера

```text
ah auth reset PlayerName
```

Команда выводит путь к файлу `anthub/auth-invitations/PlayerName.txt`. Прочитайте его через файловый менеджер, передайте приглашение владельцу и удалите файл.

### Через LuckPerms

Выдайте отдельное право модератору или группе:

```text
lp group moderator permission set anthub.auth.reset true
```

У модератора появится кнопка приглашения в карточке игрока. Также доступна `/ah auth reset PlayerName`. OP и `anthub.admin` сами по себе этого права не дают. Без LuckPerms используйте консоль.

### Закрепление имени и блокировка

Только в консоли сервера:

| Команда                      | Действие                                                                                         |
| :--------------------------- | :----------------------------------------------------------------------------------------------- |
| `ah auth reserve PlayerName` | Закрепить свободное имя перед открытием offline-сервера; затем выдать приглашение через `reset`. |
| `ah auth block PlayerName`   | Заблокировать аккаунт и отозвать доступ.                                                         |
| `ah auth unblock PlayerName` | Снять блокировку.                                                                                |

## 🗄️ Хранение и защита

- Аккаунты хранятся в PostgreSQL и не зависят от мира. Пароли — в виде хешей Argon2id; токены устройств — SHA-256.
- При включённом Auth вход и игровой TCP-трафик защищаются TLS 1.3. Пароли не передаются командами чата.
- Ключ сервера автоматически запоминается при первом подключении. Его изменение блокирует вход; подлинность самого первого подключения этим не подтверждается.
- При ошибке базы Auth не пропускает игрока без проверки. Если база недоступна при запуске, сервер не стартует.

Сохраняйте резервную копию PostgreSQL, `anthub/auth-identity.p12`, конфигурации и миров. Не публикуйте ключ, пароль базы и клиентскую папку `anthub/auth/`. После восстановления старой базы отзовите устройства и проверьте блокировки.
